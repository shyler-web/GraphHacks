Wiring the Cockpit to Real FalkorDB

Right now the cockpit fakes the graph. This lesson replaces the fake path with React UI → /api/graph/... → backend route → FalkorDB → Cypher → UI, so your demo satisfies the "graph must do real work" rule.

By the end you can replace the fake liveCypherQuery display with a real backend query and have the UI render nodes that actually exist in FalkorDB, evidenced by creating a node in the FalkorDB browser and seeing it appear in your React app after a refresh.

Why this matters

Your app src/graphsync_multi_agent_falkordb_memory_cockpit.tsx is a simulation. The entire agent memory — nodes, edges, episodes, playbooks, handoffs — is a hard-coded JS object (INITIAL_TENANTS, line 88) held in React state (tenants, line 269). The UI reads currentTenant = tenants[activeTenantKey] (line 295).

The only Cypher in the file is liveCypherQuery (line 492): a useMemo string built from the UI's maturityLevel and selectedDomain, shown in a <pre> (line 1572) and copyable (line 1561). It is never executed against a database. The "backend" tab (line 1958) is just static install instructions. Track 02 requires the graph to do real work, so this faked display is the single biggest thing standing between you and a valid submission.

This lesson makes one straight line real: the cockpit asks your backend a question, the backend asks FalkorDB in Cypher, and the answer comes back as the same JSON shape the UI already renders.

The idea

You cannot point the browser straight at FalkorDB. The official Node client, falkordb (falkordb-ts, currently 6.8.0), connects to the database and sends queries as OpenCypher over the Redis protocol — the docs state plainly that "FalkorDB is a graph database that speaks the Redis protocol. Queries are issued as OpenCypher through the GRAPH.QUERY and GRAPH.RO_QUERY commands." That is a raw TCP protocol. A browser page can only make HTTP requests; it cannot open an arbitrary TCP socket, and even a WebSocket shim would still be blocked by the server's expectation of RESP framing. So the connection must live in a Node process, and the browser talks to that process over HTTP.

Rule of thumb: browser speaks HTTP, FalkorDB speaks RESP-over-TCP. Put a tiny Node route in the middle that speaks both.

The minimal, zero-CORS way to get that Node route into a Vite app is a Vite dev-server plugin. Its configureServer hook runs in Node inside the dev server, so the falkordb client works and the UI calls it on the same origin — no proxy, no CORS headers, no second port.

The client API is small. Verified against falkordb-ts 6.8.0:

import { FalkorDB } from 'falkordb';

const db = await FalkorDB.connect({ host: 'localhost', port: 6379 });
const graph = db.selectGraph('graphsync_user1_ai_avatar_saas');
const result = await graph.query(
  'MATCH (n:ConceptNode) RETURN n.id AS id, n.title AS title'
);
// result.data is an array of row objects, e.g. [{ id: 'node_...', title: '...' }]
db.close();

graph.query() returns { metadata, data }, where each entry of data is an object keyed by the AS alias in your RETURN. That is exactly the array-of-objects your UI already maps over.

Why can't the React app in the browser talk to FalkorDB directly?

Do it

  1. Make sure FalkorDB is running and has data. If you did Lesson 0001, you already have it: 
    docker run -p 6379:6379 -p 3000:3000 -it --rm falkordb/falkordb:latest
    Open the browser UI at http://localhost:3000, select a graph, and run this to plant a marker node you will look for later: 
    CREATE (:ConceptNode {id: 'node_smoke_001', title: 'Smoke Test Node', persona_level: 0, status: 'OK'})
    Expected: a result line confirming one node created.
  2. Install the client in your project. 
    npm install falkordb
    Expected: falkordb appears in package.json dependencies.
  3. Add the backend route as a Vite plugin. In vite.config.ts, add a plugin whose configureServer opens the FalkorDB connection once and serves GET /api/graph/nodes: 
    import { defineConfig, type Plugin } from 'vite';
import react from '@vitejs/plugin-react';
import { FalkorDB, type FalkorDBClient } from 'falkordb';

function falkorApi(): Plugin {
  let db: FalkorDBClient;
  return {
    name: 'falkordb-api',
    async configureServer(server) {
      db = await FalkorDB.connect({ host: 'localhost', port: 6379 });
      server.middlewares.use('/api/graph/nodes', async (req, res) => {
        if (req.method !== 'GET') { res.statusCode = 405; return res.end(); }
        try {
          const graph = db.selectGraph('graphsync_user1_ai_avatar_saas');
          const result = await graph.query(
            `MATCH (n:ConceptNode)
             RETURN n.id AS id, n.title AS title,
                    n.persona_level AS persona_level, n.status AS status`
          );
          res.setHeader('Content-Type', 'application/json');
          res.end(JSON.stringify(result.data));
        } catch (err) {
          res.statusCode = 500;
          res.end(JSON.stringify({ error: String(err) }));
        }
      });
    },
  };
}

export default defineConfig({ plugins: [react(), falkorApi()] });
    If you prefer a separate process, the same three lines (FalkorDB.connect → selectGraph → query) drop straight into an Express route; you would then add a Vite server.proxy for /api to that port.
  4. Prove the route works before touching React. Restart the dev server, then in a second terminal: 
    curl http://localhost:5173/api/graph/nodes
    Expected: a JSON array including your smoke node, e.g. [{"id":"node_smoke_001","title":"Smoke Test Node","persona_level":0,"status":"OK"}, ...]. If you get an error here, fix it here — do not debug it through the UI.
  5. Fetch real nodes in the cockpit. Replace the faked display with a fetch. Next to your tenants state (around line 269), add a live slice that loads once on mount: 
    const [liveNodes, setLiveNodes] = useState(null);

useEffect(() => {
  fetch('/api/graph/nodes')
    .then((r) => r.json())
    .then(setLiveNodes)
    .catch(() => setLiveNodes([]));
}, []);
    Then render the proof in the Live Cypher bar (around line 1557) so the UI shows what the graph actually returned: 
    <div class="... font-mono text-[11px] text-emerald-300">
  {liveNodes
    ? `FalkorDB returned ${liveNodes.length} nodes: ` +
      liveNodes.map((n) => n.title).join(', ')
    : 'Loading real graph...'}
</div>
    Reload the app. Expected: the bar now lists real node titles from FalkorDB, including Smoke Test Node.
  6. Verify the loop closes. In the FalkorDB browser UI, create another node: 
    CREATE (:ConceptNode {id: 'node_smoke_002', title: 'Second Marker', persona_level: 0, status: 'OK'})
    Refresh the React app. Expected: Second Marker appears in the list. That is the win — the UI is reading a real graph, not a hard-coded object.
