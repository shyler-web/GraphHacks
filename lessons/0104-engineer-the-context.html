Lesson 0104 · The Engineer's Prompt

Engineer the Context

The lever that moves AI output is not how you phrase the request — it is what the model can see when it runs. Control the input, and the words stop mattering so much.

By the end you can sort your project's information into always / on-demand / never buckets, evidenced by a 5-line ALWAYS block ready to paste into AGENTS.md.

Why this matters

You are solo on a deadline. Every minute the agent spends re-reading your repo or acting on a stale assumption is a minute not building the demo. Context engineering is the highest-leverage skill in the whole playbook: teams that build structured context pipelines report 20–45% faster cycles and 3–10× first-pass success, while teams that only polish prompts plateau (10xdev.blog, 2026). It maps directly to your project: the graph is your memory layer, and AGENTS.md plus on-demand graphify query is how you feed the model without drowning it.

The idea

Stop asking “am I phrasing this correctly?” and start asking “does the agent have the right information?” (10xdev.blog). Information you give an agent belongs in exactly one of three buckets:

BucketWhat goes inYour tooling
ALWAYS
(injected at session start)		Project rules · current goal + exit criteria · locked decisions · health statusAGENTS.md
ON DEMAND
(pulled per task)		The relevant code, function contracts, and adjacent files for this taskgraphify query
NEVER
(do not inject)		The entire codebase · resolved issues · completed specs—

Dumping everything does not help — it “overwhelms the agent, which loses focus and hallucinates details from the wrong files” (10xdev.blog). It is like briefing a new hire with the goal, the constraints, and the relevant background — not a 200-page history and “figure it out.”

Before you type any prompt, name the bucket each piece of context is in. Default answer: not in the prompt. If it is not ALWAYS or needed for this task, it stays out until the agent asks.

“Here is the whole graphsync_multi_agent_falkordb_memory_cockpit.tsx (all 1,800 lines). Add a tenant switch.”

“Goal: add a tenant switch. Exit: selecting a tenant runs CREATE GRAPH and the cockpit re-reads from it. Locked: FalkorDB only, no simulation. Here is the useEffect that loads memory and the query helper — edit these.”

You need the agent to change one Cypher query. What goes in the prompt?

Do it

  1. Open your project and write the four ALWAYS facts: the rules you build under (Track 02, real FalkorDB), the current goal and its exit criterion, the decisions already locked, and current health (what runs / what is simulated).
  2. Compress each to one line. If a line is not true for every future session, it is ON DEMAND, not ALWAYS.
  3. For your next task, use graphify query "where is memory loaded" to pull only the files that task touches — never paste the whole repo.
  4. Save the ALWAYS block into AGENTS.md (the next lesson wires it into your workflow).

Write the ALWAYS bucket for your project as five lines: Project rules, Current goal + exit criterion, Locked decisions, Health status, and one Never-inject reminder. Keep it in a scratch file now; you will move it into AGENTS.md next.
