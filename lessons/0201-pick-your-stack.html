Pick Your Stack — and Write the Decision

Four stack choices are already locked in this repo — language, orchestration, tracing, deployment. This lesson gives you the framework used to lock them, so you can defend each one to a judge and reverse only the ones that are cheap to reverse.

By the end you can write a decision record for an expensive-to-reverse choice, evidenced by one five-line record in docs/decisions.md for a stack choice you can explain on demand.

Judge every stack choice on five bullets, in order — mandatory, demo-legibility per hour, debuggability for one beginner, AI-generatability, reversibility. Spend judgment where reversal is expensive; pick fast where it is cheap.

The idea

Run any stack candidate through five questions. The first is not negotiable; the last decides how long you are allowed to think.

  1. What is mandatory? FalkorDB is load-bearing (rule 3) and Track 02 fixes the features. These are constraints, not choices — everything else must serve them.
  2. Demo-legibility per hour. Can a judge see the Track 02 key-focus points — the graph doing real work — per hour invested? Stack pieces that hide the graph are cost, not progress.
  3. Debuggability for one beginner. Fewer moving parts you own. A stack you can trace end-to-end beats a clever one you cannot.
  4. AI-generatability. Popular and documented: the AI writes correct code for it, so you can direct and debug rather than invent.
  5. Reversible decision or not. A reversible decision is cheap to undo — pick fast. An expensive-to-reverse one (schema, language, contracts) deserves the analysis. See lesson 0108.

The framework-landscape review makes the orchestration caution concrete: "abstraction that obscures failure modes costs more in debugging time than it saves in setup time." [LangChain] That is the reasoning behind D2 — a framework you use 10% of breaks the simple thing you need, so the hand-rolled loop keeps the graph, not the framework, as the star. [decisions.md D2]

A decision record is five lines — Decision · Why · Alternatives · Reversibility · Revisit if — appended, never rewritten. It is the answer to "why did you pick X?" at judging. [decisions.md]

Write one decision record for a stack choice.

  1. Pick one of the four choices above — or a stack fork you actually face (e.g. which FalkorDB client, which LLM). Name it in one clause.
  2. Run the five bullets and write the single bullet that decided it as Why.
  3. Write the two strongest Alternatives you rejected, and classify Reversibility (easy / cheap-ish / expensive). If it is easy, promise yourself you will not spend more than ten minutes on it.
  4. Append the five lines to docs/decisions.md and state the Revisit if condition. That file is your rule-12 answer sheet.
