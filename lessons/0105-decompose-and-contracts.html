Lesson 0105 · The Engineer's Prompt

Decompose & Design Contracts

"Build the memory feature" is not a task — it is a wish. An agent asked for a feature returns a large diff you cannot verify. Ask instead for the smallest independently-testable slice, and fix the interface before the body.

By the end you can turn a feature wish into a named contract plus one testable slice, evidenced by three signed function contracts and one implemented, round-tripping function.

Why this matters

Track 02 asks for a lot at once: episodic, semantic, and procedural memory, handoffs, per-tenant isolation, and a UI wired to real FalkorDB. That is not one feature; it is a system of many. Prompt an agent for "the memory feature" and you get one large diff with no place to check correctness — and when it breaks, you cannot tell whether the fault is the graph model, the Cypher, or the React call site.

Engineering judgment decomposes that wish. You choose the seams, name the interface, and make the agent build one seam at a time. The prompt follows the decomposition.

Define the interface — the functions, their inputs and outputs — before any implementation. Then implement exactly one of them.

The idea

The software engineering handbook frames this as decomposability: the engineering question is whether a partial system can produce useful evidence or useful outcomes before the whole thing exists. "The smaller the portion required for either, the more opportunities the process has for early learning." A half-finished bridge carries no passengers; most software, by contrast, can be cut into pieces that are validatable on their own.

The same handbook explains why the interface is the part to pin first. Implementation details "may be inexpensive to revise," but "interfaces accumulate users … interfaces, persistent data representations, architectural boundaries … can become expensive or effectively irreversible." Cost of change is concentrated at the contract, not the body. So lock the contract, keep bodies revisable, and let the agent iterate freely underneath it.

Systems thinking supplies the test: "boundaries are where assumptions break down," and interfaces define how your service is used by the rest of the system. A contract you can read from the call site is a contract nobody has to guess at.

A vertical slice is the smallest path through every layer that ends in observable evidence — for a memory service, an HTTP call that writes one turn and reads it back. A horizontal slab (all the routes, or all the Cypher, or all the UI) produces no evidence until every layer lands. Prefer slices.

// The memory service contract — names, inputs, outputs. No bodies yet.
type Turn = { id: string; at: number; text: string };

function write_turn(user: string, session: string, text: string): Promise<Turn>;
function recall_turns(user: string, topic: string): Promise<Turn[]>;
function record_handoff(from: string, to: string, reason: string): Promise<void>;

Ask of every line: would someone know how to use this from the call site alone? If a signature needs a paragraph of explanation, the contract is still a wish.

"Build the memory feature for the FalkorDB app."

First define these three signatures and their inputs/outputs: write_turn(user, session, text), recall_turns(user, topic), record_handoff(from, to, reason). Then implement write_turn only, against FalkorDB, and show me the curl that proves one turn round-trips.

Which is the smallest independently-testable slice of the memory service?

Write the interface for your FalkorDB memory service, then spec the first slice.

  1. In a new module (e.g. src/memory/contract.ts), write every function signature the service will expose — at minimum write_turn, recall_turns, record_handoff — with typed inputs and outputs, and bodies that throw new Error('not implemented').
  2. For each one, write the one-line call-site question: would a caller know how to use this without reading the body? Fix any signature that fails.
  3. Pick the first slice: one function, its Cypher, and the exact curl that proves it round-trips. Write that three-line spec under the contract before asking the agent for anything.
