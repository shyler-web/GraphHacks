Shipping the Winning Submission

Turn the working project into a complete, submittable packet that satisfies rule 10 item-for-item — and that a judge can run, watch, and believe in under five minutes.

By the end you can assemble every artifact rule 10 demands — public repo, README with the graph data model, real Cypher, a demo video, and a live or fully documented local setup — and name Track 02, evidenced by a submission you can paste into the panel with nothing missing and disclosure of your AI assistant complete.

Why this matters

Rule 10 is a closed list, not a vibe (Graph Hacks rules): "Every submission must include: a public source-code repository; a README with setup instructions and your graph data model; the Cypher queries or graph algorithms the product depends on; a demo video showing the working project; a live deployment, or complete local setup instructions if it cannot be deployed; the track you are entering." A great build missing one bullet is an incomplete submission — so we ship to the checklist, not to feel.

Rule 7 sets the clock: the window runs "October 15, 12:01 AM IST to October 18, 11:59 PM IST," and submissions close at its end. Budget backward from 11:59 PM IST Oct 18, not from when you finish coding.

Two rules judges apply on top of the list. Rule 11: "AI coding assistants are allowed, but their use must be disclosed." Rule 12: participants "must understand the submitted code and be able to explain the graph model, the queries, the project architecture, and the technical decisions behind them." Disclosure is not a penalty — a one-line credit plus a short "key decisions" section in the README (why MERGE for idempotent writes, why one FalkorDB instance with multi-graph / multi-tenant topology) makes rule 12 easy to answer.

The 2-minute shot list

Record in this order; every clip is evidence for a Track 02 key-focus point (Graph Hacks overview). Keep it under two minutes — judges watch many.

  1. 0:00–0:15 — Problem. One sentence: an agent that forgets between sessions. Show the cockpit.
  2. 0:15–0:35 — Memory in the graph. Open FalkorDB Browser; show real nodes/edges, not a mock.
  3. 0:35–1:05 — Three tiers. Point at episodic memory (turns), semantic memory (facts/entities), procedural memory (a workflow subgraph) in one connected graph.
  4. 1:05–1:25 — Handoff. Run a two-agent task; show the persisted ledger where state and responsibility transfer.
  5. 1:25–1:45 — Tenant isolation. Switch tenant; show a second isolated graph, no bleed.
  6. 1:45–2:00 — Path behind an answer. Ask a question; show the traversed subgraph that justifies the reply.

Which rule-10 item do solo builders most often forget to include?

Do it

  1. Dedupe the repo. If a root copy and a src/ copy of the same file both exist, delete one and point imports at the survivor. Verify the app still starts before committing. Push to a public GitHub repo.

  2. Write the README. Two required sections: (a) Setup — docker run -p 6379:6379 -it --rm falkordb/falkordb:latest then your app's install/run commands; (b) Graph data model — link or embed the schema and name the tenant graph convention. Add a Key decisions line disclosing your AI assistant (rule 11).

  3. Create queries.cypher. Copy out the real queries the product runs — the episodic write, the semantic MERGE of facts, the procedural lookup, the handoff ledger write, the multi-graph tenant switch, and the path query behind an answer. One comment line per query saying what it does and which key-focus point it serves.

  4. Choose live or local. Prefer a live deployment (FalkorDB Cloud is accepted by rule 4). If you cannot deploy, the README must contain complete local setup and the demo video is mandatory ("Projects that cannot be deployed must include complete local setup instructions and a working demo video" — FAQ, Graph Hacks overview).

  5. Record the video against the shot list, upload it public, and paste the link into the README. Rehearse the rule-12 explanation until you can name the graph model, each query, and the architecture without notes.

  6. Run the check-off list at track02-checklist.html, then submit before 11:59 PM IST Oct 18 — with time to spare for the upload.
