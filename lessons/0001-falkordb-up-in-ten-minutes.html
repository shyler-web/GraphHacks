FalkorDB Up in Ten Minutes

Stand up a real FalkorDB instance and run your first query, so the graph stops being a simulation and starts doing real work.

By the end you can start a FalkorDB instance in Docker and run a Cypher query against it from Node, evidenced by your terminal printing a node you created.

Why this matters

Hackathon rule 12 requires the graph database to do real work, but your repo's liveCypherQuery and callGeminiWithBackoff are fake. Before any memory model or agent can be real, a real FalkorDB must answer a real query. That is this lesson's single win — everything else builds on it.

The idea

FalkorDB is an open-source, ultra-fast, multi-tenant graph database with vector search and Cypher, used as the agent's context layer. Two facts shape the setup:

  • It speaks the Redis protocol. Queries are issued as OpenCypher through the GRAPH.QUERY and GRAPH.RO_QUERY commands — not over Bolt or a SQL connection — which is why the client is an official FalkorDB library and not a generic driver. Docs: Getting Started — FalkorDB
  • The default port is 6379, the standard Redis channel, so your Node process connects on localhost:6379. Docs: Docker — FalkorDB

Docker is the quickest path: one command starts the server with no authentication. The falkordb/falkordb image also ships the Browser UI on port 3000 for visual exploration; the falkordb-server image is server-only for production.

import { FalkorDB } from 'falkordb';

const client = await FalkorDB.connect({ host: "localhost", port: 6379 });
const graph = client.selectGraph('agent_memory');

This is the official Node.js client the docs recommend for the language you are already working in. A node is a single entity in the graph; an edge (relationship) is a typed, directed connection between two nodes. In this lesson you create one node and read it back.

Why does the client connect on port 6379?

Do it

  1. Confirm Docker is running: docker ps — if it errors, start Docker Desktop.
  2. Start the instance. The -it keeps it attached to your terminal; --rm deletes the container when you stop it. 
    docker run -p 6379:6379 -it --rm falkordb/falkordb:latest
    Expected: logs ending with the server listening on port 6379. Leave this terminal running.
  3. In a new terminal, add the official client: 
    npm install falkordb
  4. Create first-query.mjs with the connect block above, then write and read a node: 
    const c = await graph.query(
  'CREATE (n:Memory {text: "first real write"}) RETURN n.text'
);
console.log(c);

const r = await graph.roQuery(
  'MATCH (n:Memory {text: "first real write"}) RETURN n.text AS text'
);
for (const row of r) console.log(row["text"]);

await client.close();
  5. Run it: node first-query.mjs 
    first real write
    Expected: the write result prints, then the read prints first real write. That is a real graph answering a real query.
Alternative — FalkorDB Cloud. Skip local setup entirely: create a free instance at app.falkordb.cloud/signup and point FalkorDB.connect at its host and port (with the credential it gives you). One command locally, or one signup in the cloud — either satisfies this lesson.
Troubleshooting — port already in use. If Docker reports bind: address already in use on 6379, something else holds the port (often a Redis instance). Find it with lsof -i :6379 and stop it, or map a different host port, e.g. -p 6380:6379, then connect on 6380.
