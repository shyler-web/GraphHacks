GraphHacks · Track 02 — Reference

Tool Integration Map

Where every tool lives, how it connects, and what breaks if you remove it. This is the authoritative wiring for the GraphSync stack: FalkorDB (memory), Node.js + TypeScript backend, React/Vite cockpit, Gemini (LLM), Tavily (web tool), MCP (tool protocol), LangSmith (observability), and the hand-rolled orchestrator (with LangGraph as an optional swap).

Every box in the diagram below is load-bearing. If a tool can be deleted and the demo still passes, it does not belong in the stack. FalkorDB is the one box whose removal must visibly break the app (rule 3) — that flip is the exit criterion.

Read each row as: what it does here, how it connects, and the failure it prevents — the "remove it" column is the honesty check.

ToolTavily Web-search tool the agent calls when it needs current, external facts to enrich a turn. npx -y tavily-mcp@latest with TAVILY_API_KEY; or remote MCP URL. Agent is confined to the graph — new external facts can't be discovered or grounded.
ObservabilityLangSmith (D3) Traces every LLM call and tool call so async failures are debuggable by trace. Env vars + SDK; runs/lines appear in the LangSmith project (see §4). Debugging reverts to guesswork — the only tractable path for a solo dev on an async loop.
If a judge pulls one wire, exactly one thing should fail. FalkorDB's wire must fail loudest.

3 · Runtime sequence for one prompt

The numbered path from keystroke to subgraph — this is the sequence your demo video should make visible.

  1. UI POST. Cockpit sends POST /api/run with { tenantId, sessionId, userId, prompt }. The tenant selects the FalkorDB graph key.
  2. Backend accepts. Node/TS validates input, opens select_graph("tenant:<tenantId>"), and starts a LangSmith trace for the run.
  3. LLM plan. Gemini reads the recent episodic context (previous Turns) plus the prompt and returns a plan: extract, answer, or call a tool.
  4. FalkorDB reads. The memory service recalls prior Turns, Topics and Entities for this user/session — the GraphRAG context, a traversed subgraph, not loose chunks.
  5. FalkorDB writes (MERGE). The new user Turn is written idempotently: (:User)-[:PARTICIPATED]->(:Turn)-[:IN_SESSION]->(:Session) and (:Turn)-[:ABOUT]->(:Topic). Gemini-extracted Entities/Facts are MERGE'd and linked with :MENTIONS / :HAS_FACT / :DERIVED_FROM.
  6. Tool call. If the plan needs external facts, the agent calls Tavily over MCP (web search) and/or the FalkorDB MCP server (graph query). The result is traced in LangSmith and attached to the turn.
  7. Agent reasoning / handoff. The orchestrator may pass state to the next agent; it writes a :Handoff node with :FROM_AGENT, :TO_AGENT, :HANDED_TO {at}, and :TARGETS — the shared-state ledger.
  8. Procedural remember. A successful strategy is stored as a :Workflow with :START/:NEXT_STEP and :LEARNED_FROM, so it can be replayed, not re-derived.
  9. Response + subgraph. The backend returns { answer, subgraph, sources, handoffs, traceId }; the cockpit renders the answer, the graph delta, and the handoff timeline.
Why the graph is the star (D5). Steps 4–8 all read or write the same connected graph. Episodic (Turn) links to semantic (Entity/Fact) links to procedural (Workflow) — a three-tier memory model, not three demos. Removing FalkorDB breaks steps 4, 5, 7 and 8 at once.

4 · Configuration snippets

4.1 FalkorDB npm client — connect and select a graph

// npm i falkordb
import { FalkorDB } from "falkordb";

const db = await FalkorDB.connect({
  socket: {
    host: process.env.FALKORDB_HOST ?? "localhost",
    port: Number(process.env.FALKORDB_PORT ?? 6379),
  },
  username: process.env.FALKORDB_USERNAME || undefined,
  password: process.env.FALKORDB_PASSWORD || undefined,
});

// one named graph per tenant  (multi-graph / multi-tenant topology)
const graph = db.select_graph(`tenant:${tenantId}`);

// idempotent memory write
await graph.query(
  `MERGE (u:User {id:$user_id})
   CREATE (t:Turn {id:$turn_id, timestamp:$ts, role:$role, text:$text})
   CREATE (u)-[:PARTICIPATED]->(t)`,
  { params: { user_id, turn_id, ts, role, text } }
);

4.2 Health check — the one command that proves FalkorDB is load-bearing

// npm run health  →  prints MATCH (n) RETURN count(n)
const res = await graph.query("MATCH (n) RETURN count(n)");
console.log("nodes:", res.data[0][0]);      // stop FalkorDB → this throws

Security. Never read, print, or commit .env / .env.* (except .env.example). Secrets live only in .env + the environment; reference them via process.env. Before any commit, confirm nothing secret is staged (git diff --cached).
