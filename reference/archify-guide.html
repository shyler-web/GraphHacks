Archify — Diagrams as Code

A skill that turns a description, Mermaid, or a real codebase into a checked, self-contained interactive HTML diagram. Two of this page's figures were generated by Archify itself. It exists to make rule 12 cheap: you must be able to narrate your architecture cold — a validated picture is the fastest way to rehearse that.

Use Archify from chat to generate a diagram of the cockpit's runtime, then open the HTML and explain every box and arrow. That is exactly the rule-12 explanation, practised against a checked artifact.

1 · What it is, and why you care

Archify is an agent skill (MIT, by tt-a1i) with one job: convert an idea, plan, or repository into a single portable HTML file — inline SVG, dark/light theme, optional motion, and PNG/SVG/WebM export — with no runtime dependencies. You describe the system; the agent authors a typed JSON spec; a renderer compiles it. There is no design work and no build step.

For this mission it does two things. First, it is the fastest way to produce the graph data model / architecture figure the submission packet wants (T4.4). Second, it is a rehearsal tool for T4.5: explaining the model, queries, and decisions on demand is required by rule 12, and a diagram you can point at is easier to explain than prose. Because the diagram is compiled from a checked spec, you can trust it says exactly what you wrote.

2 · What actually happens

The whole skill is one loop. The agent picks a mode, writes a candidate JSON, then runs a single finalize command whose four gates must all pass before the HTML is considered real.

The candidate JSON is the source of truth — the HTML is a build artifact. Point the agent at the JSON when you want a change ("add the FalkorDB node"), not the HTML. A passing finalize receipt ("status":"pass") proves schema validity, geometry, and a real-browser render — treat a non-zero exit as failure, never as success.

3 · Pick a mode by the question shape

Ten modes; the agent chooses from your question, or you can name one. Choosing wrong is the usual cause of an unsatisfying diagram.

ModeUse it for
architectureComponents, services, boundaries, infrastructure — what a system is made of.
workflowProcesses, approvals, tool calls, runbooks, CI/CD — steps and decisions.
sequenceAPI call chains, request lifecycles, async traces — who talks to whom, in order.
dataflowPipelines, ETL/ELT, lineage — where money or documents go.
lifecycleState transitions, retries, terminal states — where an order or job stands.
erdTables, columns, key roles, cardinality — the database schema.
classClasses/interfaces, members, inheritance, composition.
treeSingle-parent containment — repo/module layout, feature breakdowns.
timelineTimestamped events — incidents, release histories.
waterfallSpan durations and overlap — where the time went in one run.

Not for numeric charts or dashboards. When unsure, ask: node bin/archify.mjs guide "<your question>" --json.

4 · Using it in opencode

Installed globally at ~/.agents/skills/archify/, which opencode auto-loads. Just describe the task in chat — no command needed.

Use archify to map this repository's runtime architecture.
Show 8–12 core components, one primary path, external dependencies,
and trust boundaries. Put supporting detail in cards, not more edges.

It also works without a repository, on everyday subjects (leave plans, approvals, money flows), and it accepts Mermaid input — it reads the topology, then authors fresh Archify JSON.

Two setup facts. (1) The skills installer CLI needs Node 20+; it was run with nvm's v24.22.0. The Archify runtime itself only needs Node >=18 and has zero dependencies, so the system Node 18 runs it. (2) Skills are read at startup — restart opencode after installing so the running session sees it. 
# reinstall / update (Node 20+)
export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH"
npx -y skills add tt-a1i/archify --skill archify --agent opencode --global --copy --yes

5 · What is inside the skill

Everything is files — a workflow document, the CLI, one renderer per mode, typed JSON schemas, and worked examples. Nothing is hidden in a service.

6 · CLI cheat sheet

Run from your working directory; replace bin/archify.mjs with the skill's path (here, ~/.agents/skills/archify/bin/archify.mjs).

CommandDoes
finalize <type> <in.json> <out.html>Validate → deliver → strict check → real-browser check. The one command for a first draft and every repair.
validate <type> <in.json>Schema + geometry only, before rendering — cheap failure.
guide "<question>"Suggests a recipe/type for a question.
preview <type> <in.json>Live preview server while iterating.
check <out.html>Strict static checks on a rendered artifact.

The agent writes each request into its own .archify/<type>-<slug>-<timestamp>/ folder so older versions stay intact. The two figures on this page were built from JSON kept in assets/diagrams/ — the source is committed, so the diagram is reproducible.

7 · Caveats worth knowing

  • Installer needs Node 20+; runtime needs 18+. Different tools, different floors.
  • Restart opencode after installing or updating the skill.
  • A non-zero exit is never success. Repair the named gate and rerun finalize; the tool includes a repair limit so you edit, don't regenerate blindly.
  • Diagrams run with full agent permissions. Review generated files like any artifact; nothing auto-updates itself.
